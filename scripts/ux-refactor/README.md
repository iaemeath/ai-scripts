# ux-refactor — 页面布局作品库（UX Gallery）

存储与展示页面级布局设计作品的个人资产库。每个布局自包含（组件 + mock + 元数据），壳（showcase）与资产（layouts）通过注册表解耦，支持同一布局的版本演进对比。

## 运行

```bash
npm install
npm run dev    # http://localhost:3400
```

纯前端运行，全量 mock，无后端依赖。

## 代码组织（注册表模式 + 约定式目录）

```
src/
├── showcase/                    展示壳（唯一理解"展览"的上下文）
│   ├── registry.ts              ★ 注册表：glob 自动发现 layouts/**/meta.ts + v1.vue/v2.vue
│   ├── router.ts                / 画廊 · /layout/:id/:ver 单版全屏 · /compare/:id 同屏对比
│   └── views/                   Gallery / LayoutView / Compare
└── layouts/                     布局资产（自包含，按业务域整体带走）
    └── ledger-reporting/            作品：1.1 台账数据上报重构（模块级，含完整导航）
        ├── meta.ts                  作品元数据
        ├── v1.vue                   重构前完整应用壳（侧栏「台账管理」+ 5 页面切换）
        ├── v2.vue                   重构后完整应用壳（侧栏「台账数据上报」+ 5 页面切换）
        ├── pages/v1|v2/             两版各自的 5 个页面组件
        └── common/v1|v2/            各版本口径共享件（constants/api/mock/panel）
```

**作品 = 一个目录**：`meta.ts`（元数据）+ `v1.vue`/`v2.vue`（完整应用壳）+ `pages/`（页面）+ `common/`（共享件）。注册表按约定自动发现，新增作品零行注册代码。对比页双 iframe 同屏，左右两侧独立可交互（各自切页面）。

## 首批作品：1.1 台账数据上报重构（模块级 · 5 页面 × 2 版本）

设计思想：**工作台与账本分离**——
- **P1 状态与事件分离**：工作台（台账信息·常州台账 tab）承载当前状态与全部写命令；记录页（上报/归档/同步）是只追加的事件账本，只读可追溯
- **P2 生命周期投影**：状态枚举用生命周期阶段语言（新增→专业审核中→已通过/未通过），时间轴/进度口径同源
- **P3 异常驱动**：差异前排行内置列表第 1 页（县调修改橙底/新增紫标/地调待上报金底），待办前置，常态不打扰

v1（重构前）：平铺 CRUD、写操作散落各记录页、菜单按数据源组织（本地台账/省地对比/属地管理）。
v2（重构后）：角色三 tab、写命令收口工作台、账本三段式（STATS→TOOLBAR→TABLE）。

## 领域语言（借 DDD 之形，去其仪式）

- **布局 Layout**：可独立渲染的页面级作品（聚合根）
- **版本 Version**：同一布局的演化形态（v1/v2，从文件存在性推导）
- **对比 Compare**：同布局多版本的双 iframe 同屏对照
- **注册表 Registry**：壳与资产的唯一接缝（防腐层）

## 数据说明

所有厂站/设备/人名均为虚构（脱敏处理）；区划名为常州行政区划；制造商保留公开品牌。v1 数据池在 `layouts/ledger-reporting/common/v1/mock/`，v2 种子数据在 `common/v2/mock/ledger-seed.json`。
